# LLM シーン生成の性能

**言語:** [繁體中文](../zh-TW/llm-scene-performance.md) · [English](../en/llm-scene-performance.md) · [日本語](llm-scene-performance.md)

この文書では、LLM のシーン生成における性能・コスト・品質の指針を説明します。画像生成（Stable Diffusion）は別途扱います。

## 原則

1. **最小限のコンテキスト。** LLM に渡すコンテキストは、その場面に必要なデータだけにします。全キャラクターシートや全プロットを常に渡すのではなく、関係する人物・場所・直前の出来事だけを渡します。
2. **階層的な生成。** 全体を一度に生成せず、ブレインストーミング → シーン設計 → セリフ → 演出の順に段階を分けます。各段階に適した小さなプロンプトを使います。
3. **一度のリクエストで一つの成果物。** 複数の独立した成果物（例：複数シーンのセリフ）を 1 リクエストで生成せず、それぞれ独立したリクエストに分けます。これはトークン数と失敗時のコストを抑えます。

## トークン数の目安

- 1 シーンの物語テキスト：数トークンから数百トークン。
- コンテキスト（キャラクターの要約・関連シーン・設定資料の抜粋）：数百トークン以下に抑える。
- 長い生成が必要な場合は、シーンを分割して複数回に分ける。

## 失敗時の扱い

- 生成結果が期待に合わない場合は、そのまま再生成するのではなく、プロンプトを絞り込む（具体例、人物関係、文体の指定、長さの上限など）こと。
- エラーやタイムアウトがある場合は、リクエストを小さくし、再試行回数を抑えます。
- 品質は「最小で十分なコンテキスト」で担保し、過剰なプロンプトは不要です。

## コスト管理

- 不要な文字数（例：余計な前置き、繰り返し、冗長な文体指定）を減らします。
- 低コスト・低遅延のモデルと、高品質モデルを使い分けます。
- 生成結果の長さに上限を設け、無制限に伸ばさないようにします。
