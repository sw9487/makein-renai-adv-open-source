# LINE：メッセージ、既読とクロスプラットフォーム反応

**言語:** [繁體中文](../zh-TW/line.md) · [English](../en/line.md) · [日本語](line.md)

ゲーム内 LINE は実際の通信サービスには接続しない。キャラクターの連絡ハードルは人物設定で決まる。交換に成功すると、キャラクターのスタイルに合った初回の挨拶を一つスケジュールできる。LINE、対面会話、Twitter は互いに文脈を提供できるが、各行動で実際の話者、プラットフォーム、日付、ソースを保持しなければならず、あるキャラクターのツイートをプレイヤーが言ったことと誤ってはならない。

## メッセージと既読

メッセージは `GameState.messages[characterId]` に保存され、`id`、`from`、`date`、`phase`、任意の画像、`readByPlayerAt`／`readByCharacterAt` を使用する。プレイヤーがその会話を開くと、フロントエンドは `line-read` を送信し、バックエンドはそのキャラクターがまだ読んでいないメッセージを既読に標示する。プレイヤーが送ったメッセージは、キャラクターが読んだ後にのみ「既読」と表示される。未読の通知計算は `core/line-inbox.ts` にあり、フロントエンドの既に開いた位置も localStorage に保存される。

キャラクターが応答するかはモデルと文脈によって決まり、既読は返信しなければならないことを意味しない。`conversationClosed` と `expectsReply` は、自然に終わった会話と、まだ返事を待っているメッセージを区別するのに役立つ。能動的な LINE はプレイヤーの未読や既読未返信を感知できるが、おやすみ、別れなどの終わった会話を冷たく扱われたと硬直的に判断してはならない。能動ジョブと初回メッセージは `server/proactive-line.ts` に、通常のメッセージ生成は `server/chat.ts` にある。

## 画像、デートと再試行

SD を有効にすると、キャラクターは文脈に応じて人物、人物なしの物体、または風景画像のツールで画像を送れる。成功結果は本文と一緒に永続化され、失敗時に画像が届いたと主張してはならない。詳細なモデルタグとキューは [Stable Diffusion](stable-diffusion.md) を参照。

プレイヤーはゲーム設定で LINE を無効化できる。無効時は入口、LINE 交換、デート招待を隠し、サーバーは LINE チャット／既読／招待を拒否し、能動メッセージと初回挨拶をスキップする。Twitter の非公開から LINE へのツールも提供されない。古いセーブデータはデフォルトで有効のまま保持され、切り替えの選好は新しい物語とセーブデータ読み込み後も維持される。

デート招待はまずプレイヤーのメッセージを作成して LINE に表示し、キャラクターの返事を待つ。返事が完了してから相手のメッセージと、行き先の場所の確認を表示する。同じ場所を選んでも通常のトランジションを通るべきである。失敗した LINE／会話の再試行は新しい API 試行であり、以前失敗した requestId のリプレイではない。`core/navigation.ts::freshRetryAction` を参照。

キャラクターは LINE の衝突やその他の有意義な相互作用によって Twitter 投稿をできる。Twitter の文脈も非公開 LINE を誘発できる。これらの副作用は連絡権限、ブロック、runId、状態提出チェックの制約を受ける。テスト：`tests/line.test.ts`、`tests/proactive-line.test.ts`、`tests/social-bridge.test.ts`、`tests/date.test.ts`。
