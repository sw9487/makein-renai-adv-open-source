# i18n メッセージ処理と監査

**言語:** [繁體中文](../zh-TW/i18n技術說明.md) · [English](../en/i18n技術說明.md) · [日本語](i18n技術說明.md)

## 範囲

今回のスキャンでは Git 管理対象の `core/`、`server/`、`web/`、`cli/`、`bin/`、`scripts/` ソースを対象にし、無視されていない新規ファイルを以後の監査に含めます。依存パッケージ、ビルド出力、テスト期待値、開発文書、著者作成のストーリー／知識コンテンツ、キャラクター名、モデルタグ、URL、プログラム識別子、外部プロセスの生ログは UI 文字列の翻訳対象としません。`.env` は読み取りも変更もしていません。

すべての訳文は既存の `web/locales/ja.json`、`zh-TW.json`、`en.json` に保存されています。3 ファイルのセクション、キー名、データ型は完全に一致し、すべての項目は意味論的な英語キーで対応する翻訳文字列を直接参照します。例：`"invalid_requestId_format": "requestId 形式が不正です。"`。`source`／`text` のラッピングや連番キーはありません。`{0}`、`{1}` などは引数です。全言語を集約した別の JSON は作りません。既存テキスト呼び出しの互換層は繁中訳文および他言語訳文と照合します。少数の、訳文と異なる既存 API 原文は `core/service-i18n.ts` の `sourceAliases` で同じ意味キーに対応付けます。これは別の翻訳目録ではありません。

## HTTP と SSE

`server/http.ts` はルーティングとリクエスト重複排除／結果保存の完了後、`server/response-locale.ts` で返却コンテンツを翻訳します。`core/service-i18n.ts` は指定のサービスフィールドだけを処理します：トップレベル error／notice、AI ヘルス状態の message、公開作業の message、生図履歴の notice、知識ベースの error、Twitter システム通知、画像状態表示テキスト。

- ゲームセーブ、プレイヤー投稿、コメント、LLM 会話、キャラクター名、画像 URL、caption を巡回翻訳しません。
- コア例外は安定した原文を維持し、翻訳は出力境界に集約します。したがってキャンセル、リトライ、キャッシュ、永続化はインターフェース言語に依存しません。ソースに中国語の `throw Error` が残っているだけで漏れと判断できず、その原文が目録と実際の HTTP 応答にあるかを確認する必要があります。
- 完全メッセージ／完全テンプレートのマッチングを使用し、API コンテンツを断片置換しません。既知エラーは HTTP 状態コード、フィールド名、制限などの引数を保持します。未知のネイティブ／ベンダー例外は語系化された一般エラーを返し、元例外のキーやパスを直接漏らしません。
- JSON、プレーンテキストエラー（Bun がまだ Content-Type を補完していない応答を含む）、SSE をすべて処理します。SSE はフレームごとに翻訳し、`id`、`event`、`retry`、コメントを保持します。断片化された UTF-8 と CRLF は解析に影響しません。
- 言語は `X-Makeine-Language` を優先し、次に `Accept-Language` を使用します。未対応言語はデフォルトの日本語になります。EventSource はカスタムヘッダーを付けられないため、`/api/game?events=1&language=...` が追加で言語引数をサポートし、言語切り替えで購読を再構築します。ストリーム作成時に言語を捕捉し、バックグラウンドイベントが別のリクエストの言語を引き継がないようにします。
- Twitter の旧セーブの `imageStatus` は状態判定値でもあるため翻訳できません。API は UI 用に `imageStatusLabel` を追加で提供し、`twitterPostPending` の判定を保持します。

## フロントエンドと CLI

既存インターフェースは `legacy-i18n.ts` の互換層を使用します。新規サービス目録のマッチングは漢字チェックより先に実行され、英語エラーと Close、Loading などの無障礙テキストが翻訳できなかった問題を修正します。動的な `aria-label`、`title`、`placeholder` の更新は再翻訳され、原文と前回適用値をそれぞれ記録して、言語切り替えで原文を失わないようにします。`data-i18n-skip`、textarea、編集可能コンテンツ、script、style は DOM 翻訳に渡しません。Twitter 投稿／コメントと LINE の非システムメッセージはスキップ対象としてマーク済みです。

フロントエンドは同起源リクエストにだけ言語ヘッダーを付与し、リクエストの既存ヘッダーを保持し、外部サービスには送りません。

CLI も上記 3 ファイルの `cli` セクションを読み取ります。開発時は `web/locales` を読み取り、ビルド時は同じ 3 ファイルを `dist/locales` にコピーします。独立した CLI 翻訳ソースはありません。起動／更新／ヘルプ出力は `cli/i18n.mjs` を使用し、言語は `MAKEIN_LANGUAGE`、`LC_ALL`、`LC_MESSAGES`、`LANG`、システム locale で判断します。`ja`、`en`、`zh-Hant` をサポートし、`zh_TW` などのシステム形式も受け付けます。CLI にはブラウザの localStorage がなく、独立して言語を指定する必要があります。

## 検証と新規メッセージ

`bun run audit:i18n` を実行し、API／コアの直接エラー文字列、テンプレート、validateContent の assert メッセージに目録対応があるかを確認します。`bun scripts/audit-i18n.ts ui`、`server`、`english-ui` は人手レビューの候補を提供します。候補には識別子、JSX 改行、著者コンテンツが含まれ、機械的に全部を翻訳すべきではありません。監査は外部翻訳サービスを呼び出しません。

`tests/service-i18n.test.ts` は三言語／引数一致、実際の HTTP ルーティング、ヘルス状態キャッシュ、不正 JSON、メディア 404、SSE 分断とイベント ID、リクエスト言語隔離、CLI、状態の意味論、データが変更されないことを確認します。また `bun run check`、`bun run test`、`bun run build` を実行します（`bun run test` は `--timeout=40000` を含みます。postgres.js が遅いためです）。

新規 API メッセージを追加するときは、3 つの目録に同じ意味キーと各言語の完全な訳文を追加します。文の断片を連結しないでください。3 言語訳文とすべて異なる旧 API 原文に対する互換が必要な場合は、`sourceAliases` を追加します。新規サービスフィールドを追加するときは、出力フィールドのホワイトリストに明示的に加える必要があり、text／message という名のフィールドを一律に翻訳してはいけません。静的スキャンは任意の動的組み立てパスを証明できないため、新しいテンプレートと API 出力には挙動テストを補う必要があります。
