# 遊戲內 Twitter：開発契約

**言語:** [繁體中文](../zh-TW/twitter.md) · [English](../en/twitter.md) · [日本語](twitter.md)

これは本ゲーム内の架空のコミュニティであり、実際の Twitter とは接続されない。実装の入口は `core/twitter.ts`、`core/twitter-public.ts`、`server/twitter.ts`、`web/components/twitter-panel.tsx`。

## API とセーブデータ

- `GET /api/twitter` はプレイヤーの権限に応じてアカウント、投稿、通知を返し、今の時限の処理を修復・継続する。`POST /api/twitter` はプレイヤーの投稿、返信、引用、いいね、直接リポスト、フォロー／解除、承認リクエスト、ブロック／解除、削除、画像リトライを受け付ける。`PATCH /api/twitter` はプレイヤーの公開／非公開ステータスと NPC の同一スレッド内での相互連続上限を更新する。
- POST には現在の `runId` と UUID の `requestId` が必要。同一リクエストの再送は重複実行されず、ID に対応する内容が異なる場合は拒否される。ファイル読み込みで runId は変更される。生のコミュニティ状態は `GameState.twitter` にあり、通常のゲーム API ／ストリームは生のコミュニティ情報を除去し、専用エンドポイントのみが `twitterView` のフィルタ結果を返す。
- `TwitterState` は `accounts`、`following`、`requests`、`blocks`、`posts`、`jobs`、`notices`、`operations` などを保持する。新しい物語では状態が再構築される。古いジョブの結果を新しい run に書き込むことはできない。

## アカウント、オンラインとジョブ

キャラクターの handle、公開性、オンライン頻度、主動的な相互フォロー、非公開アカウントの同意ハードルは人物設定に定められている。新しい進捗ではデフォルトで佳樹を LINE の連絡先および Twitter の相互フォローとし、以後の解除は自動的には復元されない。NPC は時限ごとにオンライン率でサンプリングされ、可能な限り 6 人の利用可能キャラクターを補い、うち 4 人はプレイヤーがすでに知っている者とする。オフライン中は即時返信せず、オンライン後にキャッチアップで古いスレッドを閲覧できる。

公開アカウントは `Content.publicAccounts` に保存され、古い内容は `core/twitter-public.ts::defaultPublicAccounts` で補完される。常に公開、認証バッジ付き、継続オンラインだが、毎時限必ず投稿するわけではなく、相互フォローもしない。Editor の「人物設定 → 公開アカウント」でアカウントを追加し、アバター／Twitter バナー、概要、身分プロンプトを設定し、能力モジュールを個別に有効化してそのプロンプトを書ける。一括翻訳は名前、概要、プロンプトのみを翻訳し、ID、handle、画像は変更しない。キャラクターの友好関係、投稿、反応、補完ジョブはセーブデータに保存され、提出時に日付、run、現在の状態を照合して、古い結果が新しい進捗を上書きしないようにする。

ゲーム設定で LINE と Twitter をそれぞれ無効化でき、デフォルトは両方有効。`core/social-apps.ts` は古いセーブデータに有効のデフォルトを提供する。Twitter 無効時はトップページのボタン、ポーリング、API 操作、投稿ツール、スケジュールがすべて停止し、実行中の古い判断も提出できない。再び有効にした後に回復する。設定の切り替えは新しい物語とセーブデータ読み込み後も維持される。

「時限ごとに同一スレッド内での NPC 間の相互連続上限」はルート投稿ごとに分離され、デフォルト 3、範囲は 0〜20。プレイヤーの相互作用、新規投稿、新規コメントへの初回反応、古いスレッドの補完、友好関係、アイドルはこの枠を消費しない。枠が尽きてもキャラクターがオフラインになるわけではない。

## 可視性と関係

- 非公開アカウントの通常のトップ投稿は、作者、承認済みフォロワー、あるいはその投稿で直接 `@` されたアカウントのみが読める。非公開アカウントが公開投稿への返信で行ったコメントは、公開スレッドの権限に従って見える。返信者の非公開設定をスレッド全体に誤って適用してはならない。
- ブロックは相互フォローと承認待ちリクエストの両方を解除し、両者は相手のトップ投稿／コメントを読んだり `@` したりできない。ブロック解除してもフォローは復元されない。
- 非公開フォローはまずリクエストを送り、対象が承認または拒否する。プレイヤーは通知ページで審査する。公開アカウントには直接フォローでき、事前に知り合う必要はない。キャラクター同士やプレイヤーにリクエストを送ることもできる。
- バックエンドの `canReadPost` は返信の祖先に沿って権限を確認する。`twitterView` はさらにプレイヤーの既知／フォロー中ビューを適用する。権限を変更するたびに、トップ投稿、公開スレッド下の非公開返信、直接言及、ブロックをテストする必要がある。

## 投稿、AI と公開行動

トップ投稿、返信、引用はそれぞれ `replyTo`／`quoteTo` で関係を表し、直接リポストは元投稿の `reposts` に記録される。返信には画像を添付できない。`@handle` は未フォローのアカウントを言及できる（ブロック除く）。`#hashtag` は検索・クリック可能で、トレンドは読める投稿の新しさ、相互作用量、作者数で並べ替えられる。

プレイヤーの新規投稿／返信／引用は LLM ツールで文章を確認する。いいね、リポスト、フォロー、ブロックなどの決定的な操作は LLM を呼び出さない。NPC の `twitter_action` は一度の判断で最大 3 つの順序付きアクションを並べられ、グループ全体が検証されてから提出される。状況が許せば、能動的に LINE で私信を送ったり、会話後に投稿したり、好感度を変動させたりできる。各公開アカウントの概要と口調は `core/twitter-public.ts` にあり、ゲーム内アカウントの内容に作品、聖地マップなどの裏側ソースを記載してはならない。

東愛知新聞社は、昼に前日晩、正午に当日朝、夜に当日正午の公開トップ投稿を取得し、`twitter_news_batch` で 0〜3 件を選び、タイトル／本文／タグを統一し、ソース ID を検証する。豊橋市役所は配文を添えて他の豊橋公開アカウントの公開トップ投稿を引用できる。豊橋警察署は公開トップ投稿とコメントを巡回し、危険な内容に返信、助言、警告を行う。巡回はソースをブロックできない。

自主投稿のスケジュールは、`promotion` 店舗宣伝、`civic` 公共情報、`advisory` 安全啓発、`municipal` 地域引用、`reporting` ニュースバッチに分かれる。`patrol` は別途公開討論を巡回する。各能力はアカウントの `modules` を読み取り、専用プロンプトと組み合わせられ、あるモジュールを無効にしても他のモジュールには影響しない。頻度規則は `core/public-twitter-activity.ts` にあり、各モジュールの独立したプロンプトと利用可能アクションは `server/twitter-public-strategies.ts` にある。特殊な戦略を一つの汎用抽選関数に統合してはならない。ニュースジョブは実行前にソース時限を再走査し、未完了の前時限のタスクを少し待つ。ソースには見えるすべての公開個人・公開アカウントのトップ投稿が含まれ、個人の発言にはソースを明記しなければならない。

## 配画像、UI と通知

返信先の選択時はテキスト候補のみを送る。対象が確定し画像が含まれたら、別のリクエストはその対象の低解像度画像 1 枚のみを送る。`twitter_action` には画像能力はなく、新しい画像付きトップ投稿のみが `twitter_image_post` を使える。SD は人物、人物なしの物体、風景画像を生成できる。返信には画像添付／画像生成は提供されない。

画像付き投稿は配画像中、作者だけがプレースホルダーを見ることができ、他のアカウントは読む、いいね、リポスト、返信ができない。完了後にのみ公開され、反応がスケジュールされる。失敗時はテキストが保持され、同一投稿で画像をリトライでき、キャラクターのコメントを再び発火させなくてはならないわけではない。

左側にトップ、探索、アカウント、通知、マイページがあり、マイページは自分のトップ投稿のみを表示する。サイドバーの「フォロー中」にはキャラクターと公開アカウントが含まれる。コメント数はネストした返信を含み、並び替えは最関連、最古、いいね順を提供する。Enter で送信、Shift+Enter で改行。送信中はボタンがスピナーに変わり入力欄がロックされる。フォロー解除とブロックには確認がある。

通知ページは個別に既読にしたり、一括クリアできる。プレイヤーが関連投稿に能動的にスクロールしても既読になる。未読トークンは左側の青ドットとゲーム入口の赤ドットに使われ、既読記録は runId ごとにブラウザの localStorage に保存され、コミュニティイベント自体はゲーム状態に存在する。

## 回帰検証

新しい公開アカウントの追加は Editor を優先して使う。安定した ID／一意の handle、自然な日本語の概要と投稿プロンプト、アバター、Twitter バナー、利用可能な公式ソースリンクを確認する。モジュールは個別に設定でき、`promotion`／`civic`／`advisory` が自主投稿を、`patrol` が巡回を、`reporting` がニュースバッチを、`municipal` が引用共有を決定する。架空アカウントが世界内の公式ソースを持たない場合、アニメ聖地マップで店舗ソースを偽装してはならない。アカウント ID はセーブデータと投稿に入った後、勝手に文字を変えられない。改名が必要なら、古いセーブデータの移行を設計し、フォロー、ブロック、投稿、通知、言及をテストしなければならない。場所設定は `core/official-places.ts` にあり、アカウントデータとは分けて管理する。

ゲームの場所背景には `/assets/places-official/` を使い、公開アカウントのバナーには `/assets/twitter-official/covers/` を使う。両者は異なるフィールドと用途である。古い内容がカバーを場所背景として誤って保存した場合、`twitter-official-places-v3` アップグレードで内蔵の 7 店舗の場所と素材記録を独立生成された ADV シーン画像に変更する。カスタム背景は上書きしない。画像追加時は両方の参照とファイル存在を確認し、狭いバナーをゲームシーンとして扱ってはならない。

`tests/twitter.test.ts` は権限、スケジュール、ツール、画像、ニュース、警察、クロスプラットフォーム反応をカバーし、`tests/twitter-http.test.ts` は HTTP と公開アカウントのフォローを、`tests/twitter-ui.test.ts` はインターフェース契約をカバーする。変更後は `bun run check`、`bun run test`、`bun run build` を実行する（`bun run test` には postgres.js が遅いため既に `--timeout=40000` が含まれる）。実モデル診断 `bun scripts/twitter-live-audit.ts --live` は明示的に必要に応じて実行し、単回のモデル選択を固定比率として書くべきではない。
