# i18n 訊息處理與稽核

**语言导航 / Languages / 言語:** [繁體中文](i18n技術說明.md) · [English](../en/i18n技術說明.md) · [日本語](../ja/i18n技術說明.md)


## 範圍

本次掃描 Git 管理的 `core/`、`server/`、`web/`、`cli/`、`bin/`、`scripts/` 原始碼，並將未忽略的新檔案納入後續稽核。依賴套件、建置輸出、測試預期值、開發文件、作者撰寫的劇情／知識內容、角色姓名、模型標籤、URL、程式識別碼及外部程序原始日誌不當作 UI 字串翻譯。沒有讀取或修改 `.env`。

所有譯文均保存在既有的 `web/locales/ja.json`、`zh-TW.json`、`en.json`。三份檔案的區段、鍵名與資料型別完全一致；所有項目均使用語意化英文鍵直接對應翻譯字串，例如 `"invalid_requestId_format": "requestId 格式不正確。"`，沒有 `source`／`text` 包裝，也沒有流水號鍵。`{0}`、`{1}` 等為參數。不另建集中所有語言的 JSON。既有文字呼叫的相容層以繁中譯文及其他語言譯文比對；少數與譯文不同的既有 API 原文由 `core/service-i18n.ts` 的 `sourceAliases` 對應到相同語意鍵，這不是另一份翻譯目錄。

## HTTP 與 SSE

`server/http.ts` 在路由及請求去重／結果儲存完成後，透過 `server/response-locale.ts` 翻譯回傳內容。`core/service-i18n.ts` 只處理指定的服務欄位：頂層 error／notice、AI 健康狀態 message、發布工作 message、生圖歷史 notice、知識庫 error、Twitter 系統通知及圖片狀態顯示文字。

- 不遍歷翻譯遊戲存檔、玩家貼文、留言、LLM 對話、角色姓名、圖片 URL 或 caption。
- 核心例外維持穩定的原文，翻譯集中在輸出邊界；因此取消、重試、快取與持久化不依賴介面語言。不能只以原始碼仍有中文 `throw Error` 判斷漏翻，必須檢查其原文是否在目錄及實際 HTTP 回應。
- 使用完整訊息／完整模板匹配，不以片段替換 API 內容。已知錯誤保留 HTTP 狀態碼、欄位名、限制等參數；未知原生／供應商例外回傳語系化通用錯誤，不直接洩漏原始例外中的金鑰或路徑。
- JSON、純文字錯誤（包含 Bun 尚未補上 Content-Type 的回應）及 SSE 都處理。SSE 逐框翻譯，保留 `id`、`event`、`retry` 與註解；分段 UTF-8 和 CRLF 不影響解析。
- 語言優先使用 `X-Makeine-Language`，其次為 `Accept-Language`；不支援的語言預設日文。EventSource 無法帶自訂標頭，因此 `/api/game?events=1&language=...` 額外支援語言參數，切換語言會重建訂閱。串流建立時捕捉語言，避免背景事件沿用另一個請求的語言。
- Twitter 舊存檔的 `imageStatus` 同時是狀態判斷值，不能翻譯。API 額外提供 `imageStatusLabel` 給介面，保留 `twitterPostPending` 的判斷。

## 前端與 CLI

既有介面仍使用 `legacy-i18n.ts` 相容層；新增服務目錄匹配在漢字檢查之前執行，修正英文錯誤與 Close、Loading 等無障礙文字無法翻譯的問題。動態 `aria-label`、`title`、`placeholder` 更新會重新翻譯，並分別記錄原文與上次套用值，避免切換語言丟失原文。`data-i18n-skip`、textarea、可編輯內容、script、style 不交給 DOM 翻譯；Twitter 貼文／留言及 LINE 非系統訊息已標記跳過。

前端只替同來源請求加上語言標頭，保留 Request 既有標頭，不傳給外部服務。

CLI 同樣讀取上述三個檔案的 `cli` 區段；開發時讀取 `web/locales`，建置時將相同三個檔案複製到 `dist/locales`，沒有獨立的 CLI 翻譯來源。啟動／更新／說明輸出使用 `cli/i18n.mjs`，語言依 `MAKEIN_LANGUAGE`、`LC_ALL`、`LC_MESSAGES`、`LANG`、系統 locale 判斷；支援 `ja`、`en`、`zh-Hant`，也接受 `zh_TW` 等系統格式。CLI 沒有瀏覽器 localStorage，需獨立指定語言。

## 驗證與新增訊息

執行 `bun run audit:i18n` 檢查 API／核心的直接錯誤字串、模板及 validateContent 的 assert 訊息是否有目錄對應。`bun scripts/audit-i18n.ts ui`、`server`、`english-ui` 提供人工審查候選；候選包含識別碼、JSX 換行及作者內容，不能機械地全部翻譯。稽核不會呼叫外部翻譯服務。

`tests/service-i18n.test.ts` 檢查三語／參數一致性、實際 HTTP 路由、健康狀態快取、非法 JSON、媒體 404、SSE 分段與事件 ID、請求語言隔離、CLI、狀態語意及資料不被修改。另執行 `bun run check`、`bun run test`、`bun run build`（`bun run test` 已內含 `--timeout=40000`，因 postgres.js 較慢）。

新增 API 訊息時，在三份目錄加入相同語意鍵與各語言的完整譯文；不要拼接語句碎片。若需相容與三語譯文皆不同的舊 API 原文，再加入 `sourceAliases`。新增服務欄位時必須明確加入輸出欄位白名單，不能把任何名為 text／message 的欄位一律翻譯。靜態掃描不能證明所有任意動態組字路徑，因此需為新的模板與 API 輸出補上行為測試。
